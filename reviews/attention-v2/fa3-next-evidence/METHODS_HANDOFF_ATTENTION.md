# 供方法论研究使用的 Attention 交接材料

这是给主线程合并到 ChatGPT 研究消息的材料；本任务没有向外部对话发送内容。

请研究并纠正我们的 **GPU kernel 优化方法论**，暂时不要再列新 kernel 点子
或调参建议。目标是提高有意义实验的命中率，并找到能解释整体竞争差距的
研究路径。请区分已有事实、待测假设、信息缺口与理想化模型，指出下面的
方法哪里会系统性地把工作导向低价值或不具竞争力的方向。

我们的 Attention 工作版本在一次官方非排名 check 中通过全部 16 个前置测试
和 12 个计分形状，得分 1.233633，95% 区间 [1.215129, 1.252138]。
2026-10-25 22:57 UTC 的公开榜首快照是 2.9097；没有其代码、单形状耗时或
私有作业数据。这是历史快照，不是当前榜单查询。按我们自己的固定参考计分
模型，差距相当于整体负载时间再降 57.60%。仅把六条 full 路径减半，得分
约为 1.8891；把它们全部放到 TASK 的理想吞吐估计，约为 2.3585。
这些只是覆盖面模型，不能当作实测瓶颈或可达到的硬件下界。

每个 batch 分别计 decode 和 verify 两个负载，共六个负载做几何平均；每个
负载包含 46 层 sliding 和 16 层 full。TP8 为 16 个 Q 头、2 个 KV 头，D64，
计分输入 page1、约 80K 上下文；decode 是一个 token，verify 是八个因果 token。
滑窗精确覆盖 2048 token，full 必须覆盖所有键。新 KV 更新、norm/RoPE、
调度准备、attention、merge、输出 norm/gate 都必须留在正确的每次调用边界。
使用冷 L2 的 CUDA graph 配对重放，原始数值容差不能放宽。full decode 的
scheduler_metadata 是契约提供的合法输入；verify 内部或新增规划必须逐次计入。
不能自行缓存输入派生结果或 live task map。官方规则的现有索引文本明确允许 load_inline/native CUDA
以及镜像库；我们曾把简写进程限制过度推广为编译禁令，后来已纠正。当前完整
规则例外文本和 server checker 实现尚未完全取得，不能把本地静态检查器当成它。

不能再当成新机制的东西：现有代码已经有 GQA 头复用、FP8 Q/K 编码、精确
窗口裁剪、准备融合和新 KV 更新；自研 decode 的 merge 已融合输出 norm/gate。
B32 full 自研编译记录已有异步拷贝及 commit/wait；E4M3 编码不等于原生 FP8
tensor 指令，其记录是 F16 QK / BF16 PV 的 mma.sync。旧的实际执行 FA3 trace
已经证明它有动态持久调度和分阶段 SM90 mainloop，不能凭镜像缺源码就宣称
缺少 overlap 或 persistence。当前各条 FA3 的确切 split/task map 和硬件利用率
仍不全。两次 NCU session 超时；不是权限拒绝，也没有获得 stall/HBM 利用率。
已有活动 trace 只能定位阶段，重叠行可能包含前驱等待，不能直接从完整调用
减出 launch、merge 或 memory 瓶颈。

几个有代表性的结果：

- 准备融合加 page-address lookahead 是真实但有限的改进，工作分数由历史
  A2-11 的 1.18768 提升到 1.23363。增量 lookahead 在同场配对目标上降时
  4.82%，但同时改变生成的 buffering，不能归因于单一地址延迟。
- 把 B16/B32 sliding verify 的 split 固定为 1，确实消除了 combine，却分别
  慢 31.49% / 7.86%。少一个 launch 不是自动收益。
- 首个所谓 serial/overlap 对照被编译器把 K load 提前，原控制假设失败，因此
  没有拿它的时间宣称 overlap 有效，也没有故意把控制做慢。
- 改成原生指令可区分的 V 转换/共享发布时序后，30 次原始 oracle 检查通过，
  两套新 fixture 的配对原型降时为 5.04% / 3.89%。但较快原型在相同 nearby
  ctx4096、padded page table 的完整调用仍比当前 FA3 慢约 3.82 倍，因此否决
  生产替换，没有进入官方 check。它只能说明局部时序差异有作用。
- 当前 B1 sliding 使用 32 个 producer CTA 和 16 个 merge CTA；instrumented
  活动为 7.8 + 1.7 µs，但这不是可直接相减的完整调用分解。M16 只有八行有效。
  已准备一个固定 S16/N64/同 merge 的 G8 SIMT 廉价编译 falsifier，27 项 CPU
  检查通过，**尚无上传、GPU admission、编译、数值或性能结果**。暂停启动。
  即便这一条完整调用降时 15%，模型整体得分也只增约 1.44%，不是追榜主线。
